4️⃣ Utility/Helper Pattern (FormHelper, UIAnimations)

Mục đích: Nhóm các hàm liên quan lại thành một utility class

  • FormHelper - xử lý hiển thị/xóa lỗi trên form
  • UIAnimations - hiệu ứng entrance, transition
  • AlertHelper - hiển thị dialog, alert
  • Toast - thông báo tạm thời

Lợi ích: Tái sử dụng code, avoid duplication

5️⃣ Chain of Responsibility (Validation Rules Chain)

Mục đích: Mỗi rule xử lý validation riêng, nếu lỗi trả về, nếu OK tiếp tục rule tiếp theo

Ví dụ: LoginValidator → NotBlankRule → EmailOrUsernameRule → PasswordRule

🏗️ Layer Architecture

Tổng quát

Ứng dụng được chia thành 4 lớp chính, mỗi lớp có trách nhiệm riêng:

Lớp 1: PRESENTATION (UI)

📱 Gồm: FXML files, FXML Controllers (LoginController, RegisterController, ...)
🎯 Trách nhiệm: Hiển thị UI, nhận user input, gọi validation & service
🔗 Phụ thuộc: Validation layer, Core UI utilities
📦 Ví dụ: LoginView.fxml, LoginController.java

Lớp 2: VALIDATION (Business Rules)

✅ Gồm: Validator implementations (LoginValidator, RegisterValidator, ...)
🎯 Trách nhiệm: Kiểm tra tính hợp lệ của dữ liệu input, áp dụng rules
🔗 Phụ thuộc: Shared validation interfaces & rules (Auction-Shared module)
📦 Ví dụ: LoginValidator, ValidationRule, FieldValidator (từ Shared)

Lớp 3: APPLICATION/SERVICE

⚙️ Gồm: AuthValidatorFactory, AuthService (commented), Utilities
🎯 Trách nhiệm: Gọi validation, xử lý business logic, quản lý scene navigation
🔗 Phụ thuộc: Presentation layer, Validation layer
📦 Ví dụ: AuthValidatorFactory, ManageScene (SceneNavigator)

Lớp 4: NETWORK

🔌 Gồm: SocketClient, Shared Request/Response DTOs
🎯 Trách nhiệm: Gửi/nhận dữ liệu với server qua TCP socket
🔗 Phụ thuộc: Gson (JSON serialization), Shared DTOs
📦 Ví dụ: SocketClient.sendRequest(), SocketClient.connect()

✨ Best Practices áp dụng

🎯 Single Responsibility Principle (SRP)

Mỗi class chỉ có một trách nhiệm:
• LoginValidator chỉ validate login
• FormHelper chỉ handle form UI
• SocketClient chỉ handle network

🔌 Dependency Injection ngầm

Controllers tạo validators qua Factory thay vì tạo trực tiếp:
Validator<LoginRequest> validator = AuthValidatorFactory.createLoginValidator();

📦 Separation of Concerns

• Shared module: DTOs, Models, Validation interfaces (shared giữa client & server)
• Client module: Controllers, Validators impl, UI (JavaFX specific)
• Server module: Business logic, Database, API handlers

🔄 Immutability & Side-effect free

• ValidationResult immutable: fieldErrors = Collections.unmodifiableMap(errors)
• FormHelper static methods: không có state
• Validators không thay đổi input object

🧪 Testability

• Validators độc lập, dễ unit test
• FormHelper static methods dễ mock
• SocketClient có thể inject mock khi test

💡 Tip: Kiến trúc này tuân theo SOLID principles và Clean Code best practices
